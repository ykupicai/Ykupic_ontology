# 交接點要驗「實際餵進下一段的那份檔」

## 事故：某案場整案無聲消失

某漁電共生案（57 案場）跑產線時：

1. 案場定義檔（sitemap）**沒有「段」欄**
2. 該鄉鎮有**跨段重複的地號**
3. 分派時該地號無法判斷屬於哪一段 → **分派失敗**
4. 結果：**其中一個案場整個憑空消失**

**沒有任何錯誤訊息。** 產出的圖張數是「56 案場的張數」，看起來完整、每張都正常，
只有把案場清單逐一比對才會發現少一個。

## 為什麼驗收沒抓到

因為驗收驗的是「**我剛才產生的那份 sitemap**」，
而出圖實際吃的是「**上一輪留下來的舊 sitemap**」——兩者不是同一份檔。

多階段產線有一堆情境會造成這種錯位：
- 換模式（`single` ↔ `persite`）但沿用了舊的中間產物
- 加了 `--skip-extract` 跳過抽取，吃到上一輪的 gpkg
- 用 `--from` 從中間某段續跑，前段產物是舊的
- 手動修過中間檔，但腳本又重新產生了一份覆蓋掉

## 規則

### 1. 驗「實際餵進下一段的那份檔」，不是「你剛才驗過的那份」
驗收時對**檔案時戳**，確認它是本輪產生的。
「我確認過那份是對的」在多階段產線裡不是有效陳述——要問「**下一段讀的是哪一個檔案路徑，
那個檔的 mtime 是什麼**」。

### 2. 交接檔的必要欄位要當成硬閘門
本案的修法是：**sitemap 必含「段」欄**，並把案場定義權**收回產線**
（`build_sites_sitemap.py` 以相鄰宗地連通分量聚類產出權威 sitemap），
**臨路評估與出圖吃同一份**，案場幾何完全一致。

> 通則：**跨段交接的資料結構，缺欄位要當場失敗，不要讓它「盡力而為」。**
> 「盡力而為」在批次產線裡就是無聲丟資料。

### 3. 跳段／續跑要加一致性檢查
引擎後來補上：`--skip-extract` 時檢查「gpkg 的基地分組 vs 本次案場清單」，
**不一致就自動落回完整重抽**；`--from` 截斷前先檢查前置產物是否齊備，缺件**中文點名**。

### 4. 數量對帳是最便宜的防線
輸入 N 個案場 → 輸出應該有 N 組成果。
**每個交接點都印「進 X 筆 / 出 Y 筆」，不等就停。**
本案若在分派後印一行「案場 57 → 分派成功 56」，當場就會發現。

## 同一類型的其他實例

- 案件建檔時派工子代理回報「已完成」但實際被配額中斷（token 用量只有幾十）
  → 必須用檔案數自行核對，見 案件建入知識庫-AI標準作業與判斷準則「驗證勝於信任」。
- 子代理回報「已雙向連結」但實際只做了單向。
- 評估案件索引產生器重跑會把人工萃取欄洗回空白（已修）——同樣是「下一段吃到的不是你以為的那份」。

## 一句話

> **在多階段產線裡，「我驗過了」必須具體到「我驗的是 `<路徑>`，它的 mtime 是 `<時間>`，
> 而下一段讀的就是這個路徑」。** 否則那只是自我安慰。
