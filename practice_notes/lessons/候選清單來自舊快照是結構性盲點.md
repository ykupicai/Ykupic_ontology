# 候選清單來自舊快照，是結構性盲點——不是「資料稍舊」

## 問題

「大量圖資轉換工具」產線取周邊地籍，長期走兩段式：

1. 用**本機地籍快照**（Ver 111年2月）認出「出圖框內有哪些地號」
2. 拿那些地號**逐筆**去問農業部線上服務，換回現行幾何與屬性

看起來很安全——屬性都是線上現行值，快照只拿來「認身分」。實際上某評估案
（2026-09-04）基地西側出現大片留白，框內覆蓋率只有 82.0%／67.6%。

漏掉的是 **374-1（12,112 ㎡）與 374-2（24,225 ㎡）**，合計 36,338 ㎡，
就在基地西側 **3.9 公尺**處。

## 原因

**候選清單完全由那份三年前的快照決定：快照沒有的地號，從頭到尾不會被送查。**

該段整段重測改名並**全段重編號**，其後又以「和解分割」
（113-11-29）分出 374-1／374-2。這兩筆在快照裡**沒有任何舊地號對得上**，
於是連「問一下」的機會都沒有。

更麻煩的是，先前為了補快照盲點做的兩套自動補救**在此情境同時失效**：

- **母號縮水偵測**（快照母號面積 vs 線上同地號面積 <0.9 判為就地分割）——
  全段重編號後，兩邊的地號集合**完全不重疊**，一個也比不出來。
- **子號探測**（對母號批次探子號 1~80）——用的是**舊段名**，該段在現行版查無。

也就是說：補救機制的前提是「段名不變、只有個別地號分割」，遇到**整段重測改名＋
重編號**就整組報廢。而這件事在圖上的樣子只是「一片白」，沒有任何錯誤訊息。

## 解法

**改成「用範圍問，不要用清單問」**——把出圖框直接送服務做**空間查詢**，
一次回傳範圍內全部宗地，**不必事先知道有哪些地號**。

本例的具體出入口：農業部同一台 ArcGIS 上的地籍圖層本體
（`CadastralMap/CadastralMap_Tiled_<版次>/MapServer`，支援 Query 與分頁），
與原本逐筆用的 ring API **是同一份資料的另一個入口**——逐筆比對 126 筆
**IoU 全部 = 1.000000**、登記面積完全相同。改完 15 個既有案回測，
框內覆蓋率由 53.16%~100% 全部升到 **100.00%**，零資料遺失；
順帶把密集市區大框（1,684 筆）從「逐筆查數小時」變成 **0.3 秒**。

**同時把「覆蓋率」升為硬指標**：範圍查詢回來的就是範圍內全部，覆蓋率理應 100%；
不足即代表該處真的沒有宗地（水域、未登錄地）或服務異常，**必須明講**，
不可讓讀圖的人以為那裡沒有土地。

## 下次注意

- **凡「用 A 資料源決定要問 B 什麼」的設計，A 的完整性就是整條路的天花板**，
  無論 B 多權威、多即時。先問一句：**A 缺的東西，有沒有辦法被發現？**
  本例的答案是「沒有」——缺的東西不會報錯，只會安靜地不存在。
- **優先找「用範圍／條件問」的介面，而不是「用清單逐筆問」。** 逐筆查詢除了慢，
  更根本的問題是它把「要問什麼」外包給了另一份可能過時的資料。
- **補救機制也要問它自己的前提**。本例兩套補救都假設「段名不變」，
  而那正好是本案出事的地方。補救失效時通常沒有訊號，比沒有補救更危險。
- **留白必須是一個會叫的錯誤**。加「覆蓋率」這類可量化的完整性指標，
  讓「少了東西」在產出當下就被抓到，而不是靠人逐張看圖。
