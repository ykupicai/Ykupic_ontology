# 單反斜線的 UNC 路徑會靜默寫到本機

**現象（2026-09-16，內湖保護區案 NAS 歸檔）**：同步腳本逐檔複製到 NAS 後當場
`Get-FileHash -Algorithm MD5` 比對，回報「138 組全部相符、失敗 0」；90 秒後再清點
NAS 資料夾卻只有 119 檔。反覆補檔、反覆「驗過又變少」，一度寫成
「NAS 上有背景程式在刪除已驗證的檔案」這種結論，並準備請使用者去查同步／防毒任務。

**真因**：腳本裡的目的路徑少了一個反斜線——`"\<NAS>\<共享名>\..."`。
PowerShell **不會**把它當成壞掉的 UNC，而是當成「**目前磁碟機根目錄下的相對路徑**」，
於是整批檔案寫進 `C:\<NAS>\<共享名>\...`（實測累積 197 檔／365.6 MB）。
`New-Item`／`Copy-Item` 全部成功、`Test-Path` 為真、**MD5 也真的相符**——
因為驗的是剛剛寫到 C: 的那份。NAS 上的檔案則停在先前用正確路徑手打的那幾次複製，
所以「數量忽多忽少」。

反斜線是怎麼掉的：腳本是用 **Bash heredoc 寫出來的**，`\\` 在轉一手的過程中被吃成 `\`。

**教訓**
1. **「複製完當場驗 MD5」不能證明檔案到了目的地**——它只證明「來源與我剛寫的那個檔
   內容相同」。目的地是不是你以為的那顆磁碟，要另外驗。
2. 寫遠端／UNC 路徑的腳本，開頭就下硬檢查：目的路徑不是以雙反斜線開頭就 `throw`；
   或驗 `(Get-Item $dst).PSDrive` 是不是預期的那顆。
3. **中文路徑的腳本用 PowerShell here-string 直接寫檔，不要經 Bash heredoc 轉一手**
   （既有規則是「中文路徑用 PowerShell 不用 Bash」，這次是用 Bash 去**產生**
   PowerShell 腳本，同樣中招——規則要延伸到「產生腳本」這一步）。
4. **觀察到反常現象時，先懷疑自己的工具鏈，再懷疑環境**。「檔案自己消失」這種假設
   代價很高（會讓使用者去翻 NAS 設定），提出前應先做一個能推翻它的最小測試——
   本例只要 `Get-ChildItem $dst | Select -First 1 | % FullName` 印出完整路徑就穿幫了。
