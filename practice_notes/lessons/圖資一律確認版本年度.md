# 圖資一律確認版本年度：同資料夾內的舊檔會讓結論完全反向

## 事故經過

檢核基地是否位於**養殖漁業生產區**（農業主管機關同意農業用地變更使用審查作業要點
**第七點**：經政府核定之養殖漁業生產區農業用地，**不同意變更使用**）。

在 NAS `3. 圖資\gis圖資\產業相關\一級產業\養殖漁業生產區\` 下掃到 `BREED47.shp`
（61 KB），逕行使用，算出：

> 基地未涉及，最近生產區「國安區」距 6,453 公尺 → 判 ○

使用者指出錯誤後改用同資料夾的 `養殖漁業生產區_114_SHP\養殖漁業生產區.shp`，
結果**完全相反**：

> 基地 5 筆、兩處案場 **各 100% 落在某養殖漁業生產區內**（最近距離 0 m）

| | 舊檔 BREED47.shp | 114 年版 |
|---|---|---|
| 檔案日期 | **2016-01-20** | 2025-02-20 |
| 生產區數 | 47 | **62** |
| .prj | **無** | 有（EPSG:3826） |
| dbf 編碼 | UTF-8 | Big5 |
| 本案結論 | 未涉及（6,453 m 外） | **100% 涉及** |

十年間新增了 15 個生產區，本案所在的「安南港西區」正是新增的其中一個。

## 為什麼會踩到

1. **只掃檔名、沒看檔案日期。** 目錄列表當時只顯示 `BREED47.shp`，我沒注意到它是 2016 年的檔。
2. **`養殖漁業生產區_114_SHP` 資料夾在我掃描時還沒被解壓**（同層有 `.zip`）。
   → 掃到 `.zip` 就該問「裡面是不是更新版」，而不是逕用旁邊的裸 shp。
3. **把「無 .prj」當成只需處理的技術問題**，沒把它當成「這檔可能很舊」的訊號。
   官方近年釋出的圖資幾乎都帶 .prj；沒有 .prj 往往意味著檔案年代久遠。
4. 我當時確實對結論加了「版本不明」的保留，但**保留不能取代查證**——
   既然自己都寫出「無法確認是否為現行公告版本」，就應該當場去找新版或問使用者。

## 規則

- **凡涉及「法定禁止／不同意事由」的圖層，使用前必須確認版本年度**，並在成果中載明
  圖資名稱與日期（例：「養殖漁業生產區_114_SHP，2025-02-20」）。
- **同一資料夾出現多份同主題圖資時，一律用最新的**；有 `.zip` 未解壓就先解壓比對。
  掃描圖資時 `Get-ChildItem` **要一併輸出 `LastWriteTime`**，不要只看檔名與大小。
- **無 .prj 是「檔案可能很舊」的警訊**，不只是坐標系問題。
- 結論若寫得出「版本不明、須再確認」，就代表查證還沒做完——**當下就要補查或提問，
  不要把未完成的查證包裝成附帶保留後照常交付**。

## 連帶影響（本案）

此項為 ╳ 級障礙：民間興辦土資場不符第七點六款例外之任一款
（國防防災／行政院核定計畫或公共建設／土地徵收／**政府機關興辦**公共建設或公眾使用設施／
農業主管機關核准輔導之產製儲銷農業設施／漁業結合綠能之共同升壓站儲能設備），
故農業用地變更原則不同意，整案可行性須重新評估。
