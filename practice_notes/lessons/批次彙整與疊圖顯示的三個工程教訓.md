# 批次彙整與疊圖顯示的三個工程教訓（2026-08-19 某廠房增建案）

三則都在「大量圖資轉換工具」踩到，但**原則可跨專案沿用**。案件事實見
某廠房增建案。

## 1. 批次逐項處理：單項失敗不得阻斷「已成功項」的彙整／輸出
**坑**：`cadastre_neighbors.fetch_all` 逐段呼叫 `cmd_fetch`，某段成功筆數為 0 會
`raise SystemExit`。失敗段（＝「未登錄地段」9999-xxx，線上無此段名、**必失敗**）恰好
排在**最後一組**時，例外中斷迴圈→迴圈**後面**的 concat／寫檔整段沒跑到→前面 5 段 71 筆
成功卻沒合併出最終 `鄰地.shp`（只留分段檔），得手動 concat 補救。

**通則**：批次迴圈裡「逐項副作用＋迴圈後彙整」的結構，**每一項都要 try/except 包起來**，
單項失敗只記警告、`continue`，不可讓它把後面所有項與收尾彙整一起帶走。尤其當「必然會有
一項失敗」（如查無資料的哨兵項）時，這是設計缺陷不是偶發。回歸測試要**故意讓最後一項
失敗**，斷言彙整仍產出（`test_fetch_all_survives_one_failed_group`）。

## 2. 免登入外部服務會間歇斷線 → 要有本機 fallback、恢復後再覆核
**坑**：農業部 coagis 地籍服務（`cadastre_fetch`／`cadastre_neighbors` 都靠它）**同一天
內時好時斷**（WinError 10060；早上成功、下午斷、傍晚恢復）。斷線非程式錯誤。

**通則**：依賴免登入公開服務的產線，斷線時要有**本機快照 fallback**（本案＝本機地籍
`地籍圖資/<縣市>.shp`，母號補零格式、地號組字、圖面積＝geometry.area），並在交付標明
資料來源；**服務恢復後宜以線上重抓覆核**（本案恢復後重抓 17 筆、權屬走公有土地 API 覆核）。
不要因一次斷線就當服務不可用、也不要把快照當權威終值。

## 3. 疊圖要顯示的視覺標記：用「填色紋理」不用「邊框」
**坑**：出圖引擎對分類圖層做了 `strip_outlines()`（剝除符號自帶外框、改疊統一界線層），
所以把某分類的「邊框」設成特定顏色（本案想把特定目的事業用地設綠框）在圖上**完全不顯示**
——被剝掉了；就算不剝，單一圖層裡相鄰要素的**不透明填色也會互相蓋掉對方的邊框**。

**通則**：要讓某分類在疊圖上有可辨識標記，**用填色紋理（斜線 `LinePatternFill` 等）而非
邊框**——紋理屬填色的一部分，不會被剝外框的步驟移除、也不會被鄰要素填色蓋掉，且圖例
同步顯示、不與另設的「基地框」混淆。本案特定目的事業用地＝紅底＋綠 45° 斜線，順帶解決
與甲種建築用地同為純紅難分的問題。（曾走岔路：正規化外框、另疊一條框層，皆已移除。）
