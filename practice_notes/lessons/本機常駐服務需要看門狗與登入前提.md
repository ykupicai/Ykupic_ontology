# 本機常駐服務需要看門狗與登入前提

## 問題
LINE Bot、ngrok、uvicorn 等服務部署在個人 Windows 電腦時，容易因程序停止、電腦未登入或網路環境未就緒而中斷。

## 原因
登入啟動、使用者 session、ngrok 認證檔、環境變數與網路初始化都有時間差。

## 解法
- 啟動腳本設計為冪等，已在執行就不重複啟動。
- 加入重試機制，處理登入初期環境未就緒。
- 使用 Windows 排程工作作為看門狗。
- 記錄 uvicorn/ngrok 日誌，方便排查。

## ★ 排程雙保險的具體寫法（掃描辨識專案已驗證可用）

註冊**兩個觸發器**到同一個排程工作：

1. `New-ScheduledTaskTrigger -AtLogOn` — 登入時啟動
2. `New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(1) -RepetitionInterval (New-TimeSpan -Minutes 10) -RepetitionDuration (New-TimeSpan -Days 3650)` — **每 10 分鐘自我修復**

搭配設定：
- **`-MultipleInstances IgnoreNew`** ← ★關鍵，確保只會有一個實例，不會重複處理／重複扣費
- `-RestartCount 3 -RestartInterval 1分鐘`、`-ExecutionTimeLimit 0`（不限時）、`-StartWhenAvailable`
- `-AllowStartIfOnBatteries -DontStopIfGoingOnBatteries`
- 以 `pythonw.exe` 執行（無主控台視窗）

## 三個實務坑

1. **改設定檔後只 `Stop-ScheduledTask` 不夠**——常駐進程還活著。
   正確順序：`Stop-ScheduledTask` → 關掉殘留進程（`Get-Process pythonw | Stop-Process -Force`）→ `Start-ScheduledTask`。
2. **換帳號／換機器時要先在舊環境 `Unregister-ScheduledTask`**，
   否則兩邊共用同一來源資料夾會搶著處理、造成重複（且若呼叫付費 API 就是重複計費）。
3. **「同一份被處理兩次」＝有兩個實例在跑**（通常是重設排程留下孤兒）。
   全部 `Stop-Process -Force` 再重啟。

## 付費 API 常駐服務的兩個必要設計

- **已處理紀錄檔**（如 `.processed.json`）：沒有它，重啟就重跑、**重複扣費**。
- **啟用日門檻**（如 `SKIP_BEFORE`）：第一次上線時，防止把來源夾裡的歷史檔案一次全部送 API。

## 下次注意
若要無人值守或關機後仍可服務，應改用 Windows 服務或雲端主機。
