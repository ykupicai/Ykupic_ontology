# 段的查詢一律以段碼為主鍵——段名是會過期的顯示字串，不是識別碼

> **本篇來源**：彙整自 `cadastre-check`、`parcel-roster-verify`、`tcdgis-parcels-to-shp`
> 既有記載與 `scripts/moa.py` docstring，**非新發生的事故**。

## 核心：段名會變，段碼才是主鍵

段名是**顯示字串**，至少三種情況會讓它與你手上的資料對不上：

| 變動類型 | 實例 |
|---|---|
| 行政區改制更名（連帶段名） | 員林鎮→員林市（見 [[行政區改制更名會讓整段查詢全滅]]） |
| 整段重測改名 | 松羅一段、小南灣段下福小段在最新版次**已消失** |
| 相近段名並存 | 民權／民權一、東振／東振新（見 [[重測後相近段名同號不是同一宗地]]） |

**正解是拿段碼當主鍵、不做段名文字比對。** 段碼結構（各系統略有差異，用時對照）：

- `cadastre-check`：段碼 **6 碼** ＝ 事務所碼 2 ＋ 段 4（例 `EJ2820`）
- 完整地籍鍵 **14 碼** ＝ 事務所 2 ＋ 段碼 4 ＋ 地號 8（母號 4 ＋ 子號 4 零埋）
- TCDGIS 地段下拉的 `[xxxx]` 前綴即為 4 碼段代碼，可直接抄

## ⚠ 段碼不能用猜的

實測手猜松羅一段為 `GD0179`，送新舊地號轉換 API **回空**；正確是 `GA0895`。

猜段碼的失敗模式有兩種，一種會叫、一種不會：
- 猜錯到**不存在**的段 → API 回空（會發現）
- 猜錯到**存在**的別段 → 回一筆合法的別人的地（**不會發現**）

**段碼一律從權威清單取得**：
- `check.py <縣市> <鄉鎮> --list-sections` 列出該鄉鎮所有段名與段碼
- `nluz_query.py sections --county <縣市> --town <鄉鎮>`（免登入）
- 全國批次 CSV：`lisp.land.moi.gov.tw/MMS/Handle/DownloadQuerySection.ashx?DownloadType=csv&CountyCode=<縣碼字母>`

## 段名在最新版次查無時的正解流程

**不是「換個像的段名再試」，而是回舊版次拿舊段碼。**

1. 段名在最新版次查無 → 多半是整段重測改名
2. 往回找**哪個版次還有這個段名**，取得**舊段碼**
3. 拿舊段碼＋舊地號送內政部新舊地號對照 API，追到後繼地號
4. 追蹤成功後，**屬性查詢與 SHP 欄位一律使用新地號**，原查詢地號另存欄位保留

## ★ 連帶鐵律：回傳 14 碼必須完全相符

農業部地籍 API **查不到時會回「別筆地」，而且會跨縣市**。實測：

- 查「新北市林口區某小段第 788 號」→ 回「**臺南市永康區**某段第 231 號」
- 查「屏東縣車城鄉某段第 20-13 號」→ 回「同段 **23-2**」
- 查不存在的「某小段第 9999 號」→ 回同段「**347**」

因此 `moa.parcel()` 一律驗證回傳的 `Return14SecNo` 與請求的 14 碼完全相同，不符即拒絕，
再走新舊地號對照，追不到才回報 `MISMATCH`。

**沒有這道閘門，管線會靜默產出錯誤幾何——這是它最危險的失效模式，改動時不可移除。**

連帶效果：因為 API 幾乎總會回某筆地，「這筆地不存在」實務上以 `MISMATCH` 呈現而非
`NOT_FOUND`。看到 `MISMATCH` 的正確解讀是「此地號在該版次不存在（可能已重測、分割或段名變更）」。

## ⚠ 後繼地號只能信內政部那支

實測四筆重測案，農業部模糊比對給的後繼地號 671／687／166／23-2 **全部不是真後繼**，
正解是 641／1479／1067／179——**採信會四筆全錯**。模糊比對的結果只能當「查無」的說明，
不可當答案。
