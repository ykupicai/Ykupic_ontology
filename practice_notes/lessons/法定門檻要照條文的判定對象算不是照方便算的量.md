# 法定門檻要照「條文的判定對象」算，不是照方便算的量

分類：工程教訓 / 法規機械化
建立：2026-07-30（大量圖資轉換工具 — 十戶以上聚落 200 公尺條款）
關聯：[[圖資一律確認版本年度]]、[[法規要逐點掃完不能只查關鍵字命中的條]]、
案件成果沉澱機制、[[平台數值與本機圖資不一致先想圖層門檻]]

## 教訓一句話

把法規條件寫成程式時，**先確定條文的判定對象是什麼實體**，再挑演算法。
選錯對象時，程式跑得順、數字漂亮、結論卻可能完全相反。

## 實例：「與十戶以上之村莊或聚落最短水平距離應大於二百公尺」

條文（臺南市營建工程賸餘土石方處理及資源堆置處理場設置管理自治條例§18①3）的判定對象是
**「村莊或聚落」這個實體**，不是「基地周邊的門牌」。所以正解是三步：

1. 門牌點聚類（相鄰即同一聚落；本專案用單一連結，門檻 30／50／100 公尺各跑一次）
2. **該群**門牌數 ≥ 10 → 才成立「十戶以上之村莊或聚落」
3. 量基地到**該聚落**的最短水平距離，與 200 公尺比較

兩種看起來很自然的簡化，某漁電評估案（2026-07-29）實測會這樣壞掉：

| 簡化寫法 | 該案數字 | 結果 |
|---|---|---|
| 數「200 公尺內有幾個門牌」，不足十就過 | 200 公尺內僅 5~6 個門牌 | 答案對、**理由錯**；若周邊是大聚落而只有邊緣幾戶落在環域內，就會誤判未觸及 |
| 取「最近的單一門牌」距離判斷 | 最近門牌僅 **2.7 公尺**（基地邊上） | **結論反掉**；那幾筆是分散魚塭寮，構不成十戶聚落 |
| 正解（聚落聚類） | 最近之十戶以上聚落：案場一 328.0m／案場二 281.9m | 未觸及，且 30／50／100 公尺三種門檻結論一致 |

同一支引擎跑另一案：某里 43 個門牌的聚落距基地 157.1 公尺 → **觸及**。
兩種結論都能產出，才證明引擎不是恆為否。

## 同型錯誤之二：把義務的**適用範圍**算大（2026-07-30 追加）

隔離綠帶。辦法§6①寫的是「申請範圍土地與**相鄰農業用地**應規劃隔離綠帶或設施」，
要點§9 也寫「配置區位應與**毗鄰農業用地**相緊臨」——**只有臨農業用地那幾面要留**。
初版畫成**全周界**，等於把義務擴大到臨道路、未登錄地那幾面。

- 「農業用地」不能憑印象，要回 [[農業用地變更使用審查作業要點-重點]] **第二點第二款**：
  農牧、養殖、水利、林業、生態保護、國土保安用地——**交通用地（農路）不在其列**。
- 這種錯**不會被任何檢核擋下來**（面積比照樣達標、圖照樣畫得出來），
  但會讓業主多留綠帶、多拆建物。某案實測：全周界畫法應拆 645.94 ㎡，
  改為僅臨農業用地側後 666.30 ㎡（面積比對申請面積計算，不因留設側變短而打折）。
- **教訓：算多了與算少了同樣是錯。** 交付涉及成本的數字前，回頭確認條文的
  **適用對象（誰）、適用範圍（哪幾面／哪些筆）、計算基準（分母是誰）** 三件事都對。

## 做法要點（可移植到其他門檻條款）

- **門檻參數化並跑敏感度**：聚類門檻是人為選擇，一律跑多個值；結論不一致就回報
  「門檻敏感須人工判斷」，不要挑一個好看的值定案。
- **距離要量到條文說的邊界**：條文寫「基地」就用基地面，不要用重心或外接圓
  （測繪中心環域 API 回的 distance 是到查詢圓心的距離，必須自行重算到面）。
- **把錯法寫成單元測試**：本案 10 個單測裡有兩個專門叫「錯法一」「錯法二」，
  斷言「若照錯法會放行／會誤判」＋「正解應為 X」。這比註解有效——
  未來任何人「優化」成錯法都會被擋下來。
- **代理指標要誠實命名**：門牌 ≠ 戶（公寓多戶共一門牌會低估；廟宇、工廠、倉庫、
  農舍寮有門牌卻無人居住會高估）。輸出一律寫「門牌數」，臨界值（8~12）明寫須現地
  或戶政查證。官方資料說明若自陳「僅供參考」（門牌坐標即是戶政人工點位），
  交付口徑必須照抄那句限制，定位成篩選初判而非法定認定。

## 順帶：先確認「有沒有官方點位」再認定只能函詢

這一項原本整條列為「無官方點位圖資→須函詢五個機關」，實際上：
門牌坐標（各縣市民政局開放資料）能算聚落，國土測繪中心免認證環域 API
（`MarkBufferAnlys/{med|edu|dis}`）能算醫療、文教、鄰避設施距離。
函詢對象因此縮到社福機構與營區兩類。
**「須函詢」不該是查了一次找不到就下的結論**，開放資料平台與各部會 API 值得再掃一輪。
