# 連通分量觸及查詢框邊時，面積只是框內下限

## 現象
彌陀案以「基地中心 ±250m」框查周邊宗地，再把相接的農業用地聚合成「所在連續農業用地」，
得到 49 筆 4.38 公頃，交付時寫成這塊農地的面積。2026-10-04 加大外擴重查：
500m 為 126 筆 9.05 公頃，800m 為 783 筆 83 公頃，**仍未封閉**——4.38 公頃只是被框切斷的那一段。
（把水利用地當隔絕的敏感度分析才封閉在 12.30 公頃：連續農地是靠灌排渠道一路串起來的。）

## 為什麼危險
任何「從種子出發、在有限查詢範圍內長連通分量」的分析都有同一個盲點：框外的鄰居根本沒被查回來，
演算法不會報錯，只會安靜地停在框邊。本案結論沒翻（下限已超過 §35-1 第三款 0.5 公頃），
但如果下限剛好落在門檻內，就會把「其實很大的一塊農地」判成「零星土地」。

## 正確做法
- 判定觸框：分量內任一宗地**未被查詢框內縮容差後完全包含**＝可能有框外鄰居未查回。
- 觸框時面積標「下限」，交付寫「至少 N 公頃」，不寫成確定值。
- 下限仍在門檻內（結論可能翻轉）→ 自動加大外擴重查；下限已超過門檻 → 不必再擴（框越大筆數爆量越快）。
- 已實作於 `大量圖資轉換工具\scripts\sporadic_land_check.py`（`--max-buffer` 預設 1000m），
  判準見 _判準登記表 B 表「零星土地整體認定的聚合法」。
