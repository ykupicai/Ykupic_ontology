# 案件經驗 Obsidian 知識層 - Claude Code 規則

本資料夾彙整 {{OFFICE_NAME}}（`{{OFFICE_CODE}}`）的案件經驗，供投標、製作計畫書、評估與審查因應時參考。

> 本檔是 vault 根目錄 `CLAUDE.md` 的延伸。通用規則同樣適用：繁體中文、Obsidian wikilink、保留來源路徑、不寫入密碼／API Key／Token／個資、大量寫入前先提計畫、同名筆記先比較合併。以下僅補充案件經驗層特有規則。

## 子域

- `10_變更編定`：已完成的變更編定案件。
- `11_開發許可`／`12_變更開發計畫`／`13_容許使用`／`14_漁電共生`／`15_變更環評`：其他辦理類型。
- `16_興辦事業計畫變更`：原核准興辦事業計畫的**內容變更**（無涉用地變更編定，多以主管機關同意備查結案）。**以主管機關函文的認定為定性依據，不以案名或來源夾為準。**
- `20_評估案件`：非都市土地開發評估案件索引（彙整式，每類型一份表格，不逐案建筆記）。
- `30_通用實務`：跨案件重複使用的程序、審查、函詢、版本及完工知識。
- `40_審議答詢攻防`：「我方如何答詢」的攻防手冊（與 `02` 層同案件編號但視角不同，檔名加「-答詢攻防」後綴以免同名連結歧義）。
- `50_執行中案件`：執行案件的狀態快照；資料夾不代表全部仍在履約，生命週期以各案 metadata 為準。
- `60_審議判斷依循`：提問偏好分析與意見預測用的判準與必考題（不是案件事實）。
- `70_法規索引`／`71_核心法規全文`：法源索引與重點筆記，**引用條號的權威層**（見下節）。

## 法規層：共用唯讀區與本地補充區

`70_法規索引` 與 `71_核心法規全文` 各分兩區：

| 資料夾 | 內容 | 誰可以改 |
|---|---|---|
| `_shared/` | 由共用 repo 的 `sync_to_vault.py` 寫入（法令檢核規則匯出、法規重點筆記）。**每次同步整個覆蓋** | **不得在此編輯**，改了下次同步就消失 |
| `_local/` | 本辦公室自己的補充（地方規定、辦公室自訂筆記） | 本辦公室 |

- `_shared/` 由同步腳本建立，骨架內沒有這兩個資料夾，首次同步後才會出現。
- **要改規則或共用法規筆記，一律到共用 repo 的文字正本改、push**，不是在 vault 內改。流程見共用 repo 的 README 與 CLAUDE.md。
- 新增規則的順序：官方原文 → 法規重點筆記 → 規則檔。
- 法規條文、條號、數值門檻一律回官方法規資料庫確認；第三方彙編網站只當線索。

## 使用原則

1. 筆記是**經驗索引與摘要**，不是計畫書全文搬運；要回答「下次怎麼做、審查會問什麼、文號與時程」。
2. 正式引用計畫書內容、面積、文號時，回查原始檔（每篇筆記附來源路徑）。
3. 本層為辦公室自有案件實績，**僅供公司內部**使用，不得對外散布，也不進共用 repo。
4. 可保留申請人公司名與案件事實（地點、地號、用途、核准文號），**不得寫入**合約金額、報價策略、地主姓名／身分證字號等個資；涉及者改放 `82_Review_待人工確認` 或留白。
5. **業主保密**：案件筆記只寫專業經驗，不寫業主未公開的營業資訊（未公開的開發計畫、評估廠址、規模、商業條件），也不照抄成果原文；已經主管機關核准、公告或發文的事實可寫。評估案、未送件案原則上全部屬未公開，只寫通則。只適用新建或加深的筆記。
6. 掃描影像版（無文字層）書件，先以檔名／核准函／資料夾資訊建檔，內文標「掃描本，細節待 OCR 或人工補」，不杜撰內容。
7. 新增案件時更新對應總索引（`00_Index`）。
8. 新案件遇到既有通用觀念時，連結 `30_通用實務`，不在每篇個案重複改寫。
9. 實務訪談內容須區分「法定要求」「承辦實務」「灰色地帶／風險」，不得把口頭協調或個案寬容寫成通案合法保證。
10. 查得第一級環境敏感地、涉及原住民保留地、涉及山坡地範圍時，先讀 `30_通用實務` 對應筆記（辦公室自行建立後補連結），不得在未確認法定例外前承諾可開發。

## 知識深度與生命週期

欄位規格以共用 repo 的 `core/knowledge_schema.yaml` 為準。新建或實質更新的案件筆記，拆成 `source_depth`、`lifecycle`、`authority`、`as_of`，不要把「評估／執行中／已完成」塞進深度欄。深度三級：

- `folder_only`：只靠資料夾名建立，原始書件未讀，待補卷。
- `document_extracted`：內容來自定稿計畫書／核准函／審查紀錄，待與承辦深度訪談。
- `interview_validated`：已對談取出檔案裡沒有的執行知識。

升級路徑：`folder_only` → 讀原始書件 → `document_extracted` → 深度訪談 → `interview_validated`。舊筆記採 touch-to-migrate，不為補欄位一次性覆寫全庫。

**「知識落地」的定義**：拿「已完成案件」與承辦深度對談，確認並記錄案件執行知識（審查委員實際問什麼、哪個補正卡最久、下次會先做什麼），寫成深度案件筆記。挑案時從 `10`～`16` 挑已完成案件，不要挑 `50_執行中案件`；先讀該案既有筆記與原始書件、備好具體訪談題，再一題一題對談。

## 執行中案件時效

`source_last_modified` 只證明來源卷最後檔案時間，不證明已讀取該異動；`as_of` 才是正文狀態的內容截止日。來源有新異動（`review_status: needs_source_refresh`）時，須先重讀新增／修改文件、更新正文，才能推進 `as_of`。生命週期關鍵字只做旗標，不得自動把部分駁回、多工區撤案或契約收尾誤判為整案結案。
