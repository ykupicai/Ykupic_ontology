# {{OFFICE_NAME}} AI 協作知識庫 - Claude Code 工作規則

此資料夾是 Obsidian Vault，也是 {{OFFICE_NAME}}（辦公室代碼 `{{OFFICE_CODE}}`）的共用 AI 協作知識庫。
本骨架由共用 repo（Ykupic_ontology）的 `init_vault.py` 產生；各層規則可依辦公室實況增補，但**不得放寬下方「資訊安全規則」**。

> **跨同事／跨 session 交接**：Claude Code 的 auto-memory 是 per-user，不保證跨 session 對應同一資料夾，
> **不要倚賴 memory**。重要決策、經驗、雷點一律寫進本檔、各層 CLAUDE.md 或 vault 筆記。

## 辦公室識別

- 辦公室代碼：`{{OFFICE_CODE}}`（代碼表在共用 repo 的 `offices.yaml`，發出後不得更改）
- 新建筆記 frontmatter 加 `office: {{OFFICE_CODE}}` 與 `schema_version`；新案件編號為 `{{OFFICE_CODE}}-<原有格式>`
- 辦公室自訂欄位一律用 `x_` 開頭，核心腳本忽略、不報錯

## 分區

- `00_Index`：全域入口、整理規則。入口檔見 `00_Index/知識庫總入口.md`。
- `01_AI協作共用知識`：Claude Code 專案經驗、工作流、決策、Prompt、教訓（`50_Lessons` 放工程教訓，寫 code 前先查）。
- `02_審議資料庫知識層`：委員提問偏好、議題、預判；由審議資料庫原始資料產生。專屬規則見該層 `CLAUDE.md`。
- `03_案件經驗知識層`：已完成案件（`10`～`16` 依辦理類型）、評估案件、通用實務、審議答詢攻防、執行中案件快照、審議判斷依循、法規層（`70`／`71`）。專屬規則見該層 `CLAUDE.md`。
- `80_Inbox_同事投放`：同事放原始 Markdown 或程式碼，每人一個資料夾（用全名）。
- `81_Processed_已整理`：已整理完的投放原件。
- `82_Review_待人工確認`：敏感或需人工判斷的來源檔。
- `90_Archive`：封存與備份。

## 重要規則

1. 同事投放內容只放 `80_Inbox_同事投放/<姓名>/`；不要把 Inbox 原文直接搬進正式區，必須先萃取。
2. 正式筆記使用繁體中文與 Obsidian wikilink，每篇保留來源文件路徑。
3. **修改既有筆記一律用 Edit 局部替換，不要用 Write 整篇覆寫**：Write 會把長時間 session 裡的過期副本蓋回去，Edit 對不上字串會失敗，等於自帶「副本過期」檢查。
4. 同名筆記已存在時，先比較內容並合併，不要直接覆蓋。
5. 進行大量新增／刪除／移動前，先輸出整理計畫（要動哪些檔、為什麼、風險）並等使用者確認。
6. `70_法規索引/_shared/`、`71_核心法規全文/_shared/`、`01_AI協作共用知識/55_共用實務筆記/_shared/` 是**同步區**，由共用 repo 的 `sync_to_vault.py` 整個覆蓋，不得在此編輯（見 03 層 CLAUDE.md）。要分享本辦公室的經驗，去識別化後寫進共用 repo 的 `practice_notes/`（規則見 repo 的 CLAUDE.md）。
7. 引用法規條號以 `71` 層重點筆記為準；法規條文、條號、數值門檻一律回官方法規資料庫確認，第三方彙編網站只當線索。
8. 土地使用／開發案動工前，先依 `00_Index/知識庫總入口.md` 的查詢順序查本知識庫，讀完先摘要「沿用什麼＋避開什麼」再動工。

## 資訊安全規則（任何層級的 CLAUDE.md 不得放寬）

1. 不寫入密碼、API Key、Token、個資或未匿名的敏感資訊。
2. 發現敏感內容時，先移至 `82_Review_待人工確認`，由維護者判斷。
3. 大量寫入或移動前，先輸出計畫並等待確認。
4. `02_審議資料庫知識層` 不得反向覆蓋原始審議資料。
5. 委員姓名與提問偏好屬敏感個資，僅限公司內部風險預判、不得對外散布；委員筆記一律標 `sensitivity: restricted`。
6. 報價單、契約 docx 含金額，不入庫。
7. `03` 層可保留申請人公司名與案件事實，不得寫入合約金額、報價策略、地主姓名／身分證字號等個資。
8. 案件筆記只寫公司專業經驗（法規判斷、辦理路徑、審查攻防、時程教訓），不寫業主未公開的營業資訊（未公開的開發計畫、評估廠址、規模、商業條件），也不照抄成果文件原文；只適用新建或加深的筆記。

## 指令來源裁決

同一個 session 可能同時看到多份 CLAUDE.md（使用者全域、共用 repo、本 vault 各層、本機專案）：

1. 安全與個資規則不可被下層放寬，只能寫得更嚴。
2. 工作方法衝突時，離工作目錄最近的優先。
3. 門檻、比率等判準值以 `01_AI協作共用知識/00_Index/_判準登記表.md`（辦公室自行建立）為準，不以任一份 CLAUDE.md 的複述為準。

## 維護者例行工作

- 建置與同步指令見共用 repo 的 README：`init_vault.py`（建骨架）、`sync_to_vault.py`（更新規則與法規筆記）、`vault_audit.py`（健檢）。
- 大量建檔、同步或整理後，以及宣告完成前，都跑一次 `vault_audit.py`，格式錯誤須為 0。
- 建議建立每日備份（vault 快照放在 vault 之外的資料夾）；備份細節由辦公室自訂。
